## Compare


| Sorting Algorithm         | Time Complexity               | Space Complexity | Notes / When to Use                                                                                     |
| ------------------------- | ----------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------- |
| **Insertion Sort**        | O(n²)                         | O(1)             | Simple, in-place, stable. Efficient for small or nearly sorted arrays. Not suitable for large datasets. |
| **Quick Sort**            | Avg: O(n log n), Worst: O(n²) | O(log n) (stack) | Fast in practice, in-place, unstable. Worst-case can be avoided with randomization.                     |
| **Tree Sort (BST-based)** | Avg: O(n log n), Worst: O(n²) | O(n)             | Insert elements into BST and in-order traversal. Unstable. Worst-case occurs with unbalanced BST.       |
| **Heap Sort**             | O(n log n)                    | O(1)             | Uses heap. In-place, not stable. Good for memory-limited scenarios.                                     |
| **Merge Sort**            | O(n log n)                    | O(n)             | Stable, works well for large datasets and linked lists. Predictable performance but needs extra memory. |
| **Bucket Sort**           | O(n + k)                      | O(n + k)         | Very fast for uniformly distributed integers/floats. Not comparison-based. Requires extra memory.       |


## Slowest → Fastest (general/average case)


1. **Insertion Sort → O(n²)**  
   - Very slow for large datasets. Good only for small or nearly sorted arrays.

2. **Tree Sort (BST-based) → Average: O(n log n), Worst: O(n²)**  
   - Average is O(n log n) if BST is balanced; worst-case (unbalanced) is O(n²).

3. **Quick Sort → Avg: O(n log n), Worst: O(n²)**  
   - Fast in practice, especially with randomized pivot. Worst-case is rare.

4. **Heap Sort → O(n log n)**  
   - Guaranteed O(n log n), slightly slower in practice than Quick Sort due to more swaps.

5. **Merge Sort → O(n log n)**  
   - Always O(n log n), stable, predictable, slightly slower in practice than Quick Sort for in-place variants.

6. **Bucket Sort → O(n + k)**  
   - Can be faster than O(n log n) if `k` (number of buckets) is reasonable and data is uniformly distributed.

## Notes:

- For large random arrays, Quick Sort is usually the fastest comparison-based sort in practice. (less space complexity than Merge Sort - O(log n) vs O(n)).
- Merge Sort is stable and predictable.
- Heap Sort is in-place, but a bit slower in practice.
- Bucket Sort can be even faster than O(n log n) if the data is suitable (uniform distribution).
- Insertion Sort is mostly used for small arrays or nearly sorted arrays.
