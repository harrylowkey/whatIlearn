# Merge Sort Complexity

## 1️⃣ Time Complexity: O(n log n)

Time complexity = how many operations the algorithm performs.

**Merge Sort works like this:**

1. **Divide:** split array in half → takes O(1) (just compute mid)
2. **Recursively sort** left and right halves
3. **Merge:** combine two sorted halves → takes O(n) for this level (each element is looked at once)

**Recursion tree idea:**

- Top level: merge n elements → O(n)  
- Next level: merge 2 halves of size n/2 → O(n/2 + n/2 = n)  
- Next level: merge 4 quarters of size n/4 → O(n/4 * 4 = n)  

So **at each level**, merging takes O(n).  

**Number of levels** = log₂(n) (because we split in half each time)  

✅ **Total time** = O(n) * O(log n) = O(n log n)

---

## 2️⃣ Space Complexity: O(n + log n)

Space complexity = how much memory the algorithm uses.

**a) Extra array for merging**

- Merge Sort creates temporary arrays to merge two halves.
- Each merge operation for n elements needs an array of size n (or you can reuse the same temp array).
- **Extra space for arrays** = O(n)

**b) Recursion stack frames**

- Maximum recursion depth = log₂(n)
- Each recursive call uses O(1) memory for variables and indices
- **Stack memory** = O(log n)

✅ **Total Space Complexity** = Extra arrays + Stack memory + O(1) = O(n) + O(log n) + O(1)

> O(n) dominates O(log n) for large n, so often simplified as **O(n)**  
> But strictly speaking, it’s **O(n + log n)**

---

## 3️⃣ Key Difference from Time Complexity

- **Time complexity** counts operations per level × number of levels → O(n log n)  
- **Space complexity** counts memory used at a time → extra arrays + recursion stack → O(n + log n)

> Notice: for space, we **don’t multiply by the levels**, because memory is reused at each level (you don’t keep n elements × log n in memory simultaneously).
